# Agent Note: 云电脑配对响应错误应指出桌面端阶段

Status: implemented

## Problem

在线云电脑详情显示“网关返回的数据不兼容”，但连接失败发生在手机读取绑定状态后、等待桌面完成加密配对响应期间。通用版本提示没有说明是桌面断开，还是桌面返回的控制响应无法验证。

## Decision

Rust relay 在等待桌面授权响应时区分通道断开与协议响应错误。断开时提示保持两端在线、重启或更新桌面网关后重试；解密或响应解析失败时提示检查桌面网关与手机版本兼容性。绑定身份、Noise 握手、桌面预览密钥和安全码校验继续 fail-closed，错误不能授权连接或替换已保存密钥。

其他 relay 握手步骤也保留固定阶段名称的内部协议错误，便于后续定位，但界面只展示白名单文案，不显示响应正文、密钥或服务器诊断。

## Alternatives considered

- 忽略桌面响应并按在线状态启用云电脑，会绕过用户明确的桌面批准和密钥验证，不安全。
- 将所有协议错误显示为版本不匹配，无法区分连接中断与不兼容响应，排障方向不明确。
- 自动重发配对请求会掩盖桌面处理状态并产生额外请求，因此保留只读状态核验和明确的重试提示。

## Testing

Rust relay 的 Flutter/iOS 模拟器构建通过，Flutter analyze 无问题。完整 Flutter 套件 546 项通过、5 项条件跳过；错误文案回归分别覆盖桌面断开和不兼容响应的中英文映射，详情弹窗回归确认配对错误时没有连接按钮。Rust 套件 86 项通过、1 项忽略；TLS 本机测试需将 `localhost` 加入 `NO_PROXY`，避免测试请求被本机代理拦截。已有 iPhone 18 Pro 模拟器的实际云状态重复返回“desktop gateway returned an incompatible pairing response”，确认失败发生在加密授权响应读取阶段。只访问一台模拟器中的设备状态，没有操作实体手机或发送会话内容。

## Consequences

连接失败继续阻止授权，错误现在指出桌面端响应阶段，并为用户提供更新和重试方向。仅凭手机端结果仍不能断定桌面安装包具体版本，进一步确认版本需查看对应桌面网关的本地版本信息。
