# Agent Note: 聊天图片本地预处理与按发送上传

Status: implemented

## Problem

选完附件就向网关上传，输入区必须等上传和图片回读才稳定；撤下未发送的附件也无法撤回已经传过的字节。HEIC 不在网关识别为图片的格式中，选进聊天时可能只显示文件图标。用户要求选图后提前转换为 JPG，且转换和上传不能占用发送按钮。

## Decision

输入区按完整会话及编码账号暂存所选文件。选图只读本地素材，不上传或回读网关。iOS 的 HEIC／HEIF 缩略图使用 ImageIO 先生成 320 像素长边版本，完整 JPEG 在后台准备；常用格式直接从本地字节解码缩略图。现有 JPEG 不重复压缩，统一用 `.jpg` 后缀。其他图片单张顺序编码，长边最多 2560 像素，质量 88，透明区域铺白，动画只取首帧。普通文件保留原始内容，旧草稿里的网关附件引用仍然可用。

发送按钮不等待编码，也不换成转圈。点击捕获本条文字、设置和附件，等已启动的编码完成后才上传，再用回执中的 ID 提交消息。附件显示各自的准备与上传进度；同一提交进行时再次点击不创建第二份请求。每件已确认上传写回作用域草稿，后续失败时复用这些 ID。只在前台和原会话权限仍有效时继续发新请求；退到后台保留已在途的回执，不恢复排队发送。未知上传仍由既有待核实记录拦截重放。

键盘收窄聊天视口时，附件、引用和工具条使用输入框与发送控件以外的剩余高度滚动。极低视口下输入框和发送控件也可滚动，初始从发送端显示；附件不把发送控件挤出屏幕。

待发送的本地图从全屏预览进入编辑。彩色笔迹、文字、顺时针 90° 旋转和框选马赛克可撤销、重做。预览和导出共享坐标与画布；保存合成 JPEG，仅替换作用域内原来那张图，取消不改变草稿。发送只引用合成后的字节，马赛克不作为可分离遮罩上传。历史图及已上传的引用维持只读。

## Alternatives considered

- 点击发送才启动 JPEG 编码，没发送就不消耗编码资源；但把完整编码延迟放进提交路径，选图后编辑的时间无法用于准备。
- 选择时把文件传到网关，提交只携带 ID；网络良好时点击后等待更短，但未提交的字节也会离开手机，选图预览还会受网络影响。
- 兼容图库导出只覆盖系统相册输入，能复用系统对 HEIC 的转换；但 Files 入口仍可返回 HEIC，并且会等全图转换才把控制权交回输入区。
- 把原图和可编辑图层同时保存在附件中可跨次编辑；但这要求扩充附件协议，并可能把马赛克下的原始像素一并发送。仅提交已合成的 JPEG。

## Testing

附件、编码、会话 ViewModel 和窄屏输入区共 78 项定向测试通过，覆盖发送前零上传和零回读、慢编码和慢上传期间的发送控件、重复点击、部分成功复用回执、后台和账号切换、无效图片和大小限制，以及中文窄屏键盘下附件横滑和发送控件。iPhone 18 Pro／iOS 27.2 模拟器运行 `integration_test/ios_chat_photo_test.dart` 两项通过：真实 HEIC 文件字节走 iOS 原生缩略图和 JPEG 通道；编辑夹具断言取消、撤销／重做、旋转后尺寸、画笔与文字颜色以及马赛克区域的像素变化。两项都向夹具 Repository 验证只有点击发送才上传合成字节；未使用真实云连接或物理设备验收。

## Consequences

选图和编辑期间不向网关发送附件，编辑时间可用于准备 JPEG。点发送后仍需要实际网络上传，系统图库中未下载的照片仍需系统取回，未测量真实链路吞吐。源文件至多 20 MiB、与引用合计每条 10 项，进程内至多暂存 64 项、源文件合计 64 MiB；派生编码和解码有额外内存开销。新选文件及其编辑不增加数据库字段，App 进程结束后仅保留已有的持久草稿字段和上传回执。合成 JPEG 不保留可拆分图层，也不保留透明度、动画和编辑前的原图质量。若以后需要跨进程恢复未发图片，须另定私有落盘、清理和账号隔离策略。
