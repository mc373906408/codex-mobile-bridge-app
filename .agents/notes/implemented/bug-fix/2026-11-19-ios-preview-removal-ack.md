# Agent Note: iOS 并发撤回通知预览后各自确认成功

Status: implemented

## Problem

云账号重新登录先禁用旧绑定并并行清理各台电脑的通知预览，再发出认证请求。iOS 的 `removePreview` 每次都推进全局通知代次；前一笔删除已写入磁盘，回到主线程回复时却可能因后一笔推进代次而报 `cloud_preview_unavailable`。两台已配对电脑就能触发，重登在发送登录请求前中止，页面显示通用设备功能错误。

## Decision

`removePreview` 入队前仍推进通知代次，并继续在原有串行队列执行撤回事务。事务成功后在主线程按移除的回执安排清除系统通知，直接确认成功；撤回回执不返回预览数据，也不授予通知权限，不受后续代次变化影响。验证或事务真正失败时仍返回错误，由调用方停止重登。其他方法及通知展示、点击仍受原有代次和权限校验约束。

## Alternatives considered

- 在 Dart 层逐台等待撤回，能避开同一批调用推进代次，但无法避免应用前后台切换或其他通知操作造成同一误报，也改变了所有平台的清理策略。
- 在登录时忽略预览错误能直接解除界面阻断，但现有错误码也代表真实撤回失败。只有原生事务成功才确认撤回，避免持久状态未清理时仍继续使用账号。

## Testing

`flutter test integration_test/ios_cloud_preview_test.dart -d <模拟器 ID>` 通过实际 Flutter 方法通道写入两条合成预览，并并行撤回。两笔返回成功后，用新绑定身份重新写入同两台电脑，确认旧预览登记确实删除；非法电脑标识仍报错。iOS 27.2 模拟器上，修复前并行撤回复现 `cloud_preview_unavailable`，修复后两项均通过。普通构建的 Swift 策略测试 30 项、Flutter 全套 551 项通过（5 项条件跳过）。测试不接触生产账号、密码或推送。

## Consequences

成功撤回不会因其他电脑的撤回或通知状态变化而阻断重登，不需删除配对或修改数据格式。代价是桥接层分别处理撤回确认和可被作废的通知结果；不能把返回预览内容或授予权限的方法移入撤回分支。真实存储故障仍需要处理，模拟器测试不代表实机签名或官方云登录已验收。
