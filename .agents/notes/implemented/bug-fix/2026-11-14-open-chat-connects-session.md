# Agent Note: 主动打开聊天时直接恢复原会话

Status: implemented

## Problem

用户从列表点击聊天后，App 只读取历史；网关返回可恢复但未连接的状态时，还要求点击“继续会话”。用户明确要求省去这一步。桌面 Web 对可恢复的桌面会话已有打开时连接的行为，App 的额外按钮阻断了直接进入对话的流程。

## Decision

聊天列表和工作台聊天入口把主动选择通过 `activate: true` 传给 `openSession`；读取当前身份和会话能力后，对未连接且允许恢复的原会话提交一次既有恢复操作。保留 computer/provider/entry/environment/session 身份，沿用原生前置核验和落盘回执。输入区上方展示连接进度，失败后提供“重试连接”，避免提示随长聊天滚出屏幕；已连接或不支持恢复的会话不发送恢复请求。

`openSession` 默认仍只读取，后台恢复、连接监听、通知跳转、消息编辑后的刷新及手动刷新不隐式激活会话。自动恢复结果未知时保留待核实操作；重新打开、刷新或订阅更新不得再次提交，用户先在电脑核对再按既有流程标记。只有明确的新选择或重试才产生一次激活意图，不发送聊天消息、审批或停止任务。

恢复请求串行执行并在提交前再次读取当前账号作用域的未决记录；记录读取失败也不发送。等待期间的后台、选择代次、账号或认证变化使原意图失效，迟到结果不能激活另一条聊天。重试沿用相同核验入口。

## Alternatives considered

- 在每次快照发现未连接时自动恢复，覆盖所有入口最直接，但会让轮询、通知和后台恢复启动会话，也可能重放结果未知的操作；只消费主动选择的一次意图。
- 把所有 `openSession` 调用默认改为激活可减少调用处改动，但该方法也用于消息编辑和授权恢复后的读取，因此使用默认关闭的显式参数，仅为主动入口开启。
- 直接删除“继续会话”按钮可缩短页面，但无法启用输入；复用现有恢复接口并保留失败后的手动重试。

## Consequences

主动打开聊天省去一次“继续会话”点击，失败时保留历史及可见重试，代价是首次打开可能等待原会话恢复。恢复可能让原桌面打开对应聊天或启动其既有后台接续；用户主动打开属于此次授权意图，普通刷新和通知不包含该意图。连接仍受电脑在线状态、会话能力与原生授权核验约束，不能通过换账号、执行主机或重复提交绕过。真实请求结果未知时保留人工核对步骤，不将它伪装成可自动重试的普通断线。
