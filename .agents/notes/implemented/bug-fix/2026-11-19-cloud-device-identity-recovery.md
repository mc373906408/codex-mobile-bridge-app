# Agent Note: 保留原绑定密钥并恢复丢失的云设备身份

Status: implemented

## Problem

桌面已明确批准同一台 iPhone，云目录也返回 `active`，但网关在 Noise 握手结束后拒绝授权请求。对截图对应的网关和唯一运行的 iOS 模拟器进行核对时，手机的控制公钥匹配桌面原记录，通知预览公钥不同，手机本地缺少原安全码。旧客户端把本地证明缺失的 `active` 绑定送入首次配对分支。另一个丢失密钥的途径是 SQLite 缺失电脑记录时，自动发现直接覆盖安全存储中的原绑定凭据。此次现场证据能确认预览密钥不匹配，具体覆盖发生的时间无法从现有日志确定。

## Decision

单电脑密钥丢失后的当前界面与授权规则见[选电脑后扫码](../feature/2026-11-19-select-computer-and-pair.md)，不再重新登记整部手机。本篇保留原密钥恢复及其验证证据。

已获准的在线绑定走原身份的 `authorize`。手机持有原控制和预览密钥时，从桌面的认证响应恢复缺失的预览证明。发现阶段优先读同一绑定的安全存储，核对账号、登记身份、网关控制公钥和已有安全码，再补回 SQLite 电脑索引。只为云目录中的新 `pending` 绑定生成凭据。已保存的密钥独立于一次发现的完成状态。

已退役的整机登记流程曾使用既有安装登记接口创建新身份，在联网前把新安装 ID 及控制私钥存入安全存储。登记响应丢失时复用同一身份。该流程需要所有电脑重新批准，现行客户端在原密钥不可用时改用单电脑重新配对。

## 记录归属

- [配对响应错误](2026-11-19-cloud-pairing-response.md)持有阶段诊断，本篇补齐本地凭据恢复和明确更换手机身份的流程。
- [云状态边界](2026-11-04-cloud-state-boundaries-and-legacy-removal.md)持有撤权、通知与业务权限隔离。本次沿用自动发现及桌面批准。
- [已保存的身份与重连](2026-11-05-connecting-conversation-list.md)持有既有凭据可用时的聊天进入流程。本篇处理凭据不可用的分支。
- 活跃提案中的[云聊天恢复](../../proposed/bug-fix/2026-11-05-cloud-chat-recovery-and-notice-scope.md)持有已连接聊天的断线恢复，与密钥丢失属于不同故障。没有完全吸收或需归档的笔记。

## Alternatives considered

- 继续使用已授权的控制公钥可以省去重新登记。桌面安全码也绑定双方的预览密钥，接受新预览公钥会改变已核对的身份，因此沿用明确授权的流程。
- 重装清库能建立新安装身份，但会清除草稿、直连、通知设置和未知写入。使用当前应用数据中的凭据更换可以保留这些记录及作用域。

## Testing

Rust 用真实 WebSocket 和 Noise 验证已有授权绑定补齐本地证明，并用 HTTP 夹具验证新登记使用固定安装 ID、服务端验证公钥及旧绑定隔离。真实 Flutter FFI 验证找回原索引、缺失密钥时保留安全边界，以及原有授权恢复和通知撤回。Flutter 回归覆盖登记响应丢失后重试、取消确认、新安全码出现和桌面批准前不可连接。窄屏以 320 像素宽和 1.5 倍字号复测。

Flutter 静态分析通过，551 项测试通过，5 项条件跳过。Rust 89 项通过，1 项忽略。真实 FFI 11 项和桌面 HTTP 契约 1 项通过。现有 iPhone 18 Pro 模拟器覆盖安装并启动，安装产物的原生二进制和 Flutter 内核内容与构建一致，启动前 SQLite 哈希保持一致。针对截图中同一网关复测到「重新登记此设备」确认页。真实账号的新身份登记、桌面批准和聊天列表读取待用户确认后验证。

## Consequences

原密钥尚在时可恢复同一绑定及草稿。原密钥丢失时，单电脑重新配对需要云登录凭据和对应电脑在线。旧草稿及未知写入记录仍属于原绑定。
