# Agent Note: 云电脑默认显示系统名称

Status: implemented

## Problem

用户的两台云电脑都显示 Desktop，无法区分。桌面登录注册默认写入固定名称，App 的已有 Computer 又保留首次目录名称。已授权网关的 `/api/auth` 已返回自身 `computer.name`，可以补齐旧目录默认名。

## Decision

显示优先级为本机手动别名、已取得的自动名称、原 Computer 名称。云目录的非默认名称直接更新自动名称；目录仍为 Desktop 时，仅对当前账号、已验证且获准连接的在线设备，通过已有认证接口读取系统名称。补名读取独立于目录同步，失败不阻断设备卡片或现有会话；同一发现代次的成功读取只做一次，迟到结果重新核对账号、绑定、公钥和权限。

自动名称放在现有 UiPreferences 的 presentation 映射中，键复用包含服务器、账号、绑定和公钥的 `computerNameKey`，保留离线和重启后的显示。运行中的 Computer、密钥、绑定、草稿和权限不因名称变化而替换。本地手动别名继续优先。桌面端后续注册默认名称同步改为本机 hostname，已有设备不重登、不重新登记、不轮换凭据。

## 记录审计

- [本地设备名称](../feature/2026-11-07-local-computer-names.md)：部分重叠，保留手动别名和稳定业务对象，增加自动名称来源与优先级。
- [云状态边界](2026-11-04-cloud-state-boundaries-and-legacy-removal.md)：无关，该篇持有权限和通知隔离；补名遵守相同账号及目录授权约束，不改变其机制。
- [云目录错误](2026-11-14-cloud-directory-error-context.md)：无关，网络不可达的错误提示不由名称修改处理。
- 已检索活跃名称、hostname、目录和重命名记录；没有重复提案或需要归档的决定。

## Alternatives considered

- 只修桌面注册默认值最小，但现有已登录设备仍保留 Desktop，且重新登记会轮换令牌；使用现有认证接口补名，无需退出重登。
- 改写 Computer.name 可复用数据库列，但 name 参与完整对象相等判断，会干扰连接恢复的迟到结果检查；自动显示名独立保存。
- 用手机自己的 hostname 或用服务器 IP 区分可避免额外读取，但分别指向错误设备或共享云服务器；只接受对应电脑的目录或已认证返回值。

## Testing

新名称测试与相关发现、别名、首页测试共 44 项通过；扩展到全部云服务/电脑及会话模型测试为 210 项通过、1 项原生入口按既有条件跳过。覆盖双设备实际系统名、目录变化、别名优先和重启缓存、在途读取合并、权限撤回/换钥/退出/后台后的迟到结果、读取失败不影响可连接状态。`flutter analyze --no-pub` 无问题。

Xcode Debug 构建并覆盖安装于 iPhone 18 Pro / iOS 27.2 模拟器。Device Hub 的实际页面与可访问性树确认原两张 Desktop 卡片分别显示 CHINAMI-I4UPUL6 和 wakendeMacBook-Pro.local，均在线；无真实账号退出、重新登记或系统改名。证据保留在 `.tmp/cloud-computer-names-20261114/`。桌面端注册默认值由其同日 cloud-gateway-hostname 笔记持有，42 项账号测试和 4 项模块边界测试通过；桌面运行程序未重启或重新安装。Android 本机 SDK/JDK 缺失，未更新 Lenovo 真机。

## Consequences

已有获准设备无需重登即可区分，名称缓存不影响业务身份和手动别名。代价是首次显示旧默认名时增加一次被动认证读取及显示偏好写入；成功结果在当前发现代次内复用，失败后随现有目录轮次重试。未获准或离线的旧设备仍无法读取系统名称，保留原名或上次自动名称；同名主机仍可通过本机手动别名区分。自动名称仅用于展示，不能用于身份合并或授权。
