# Agent Note: 连接等待的聊天列表与已验证设备重连

Status: implemented

## Problem

选中电脑后，`selectComputer` 清空上一连接状态并开始异步认证。此时 `authenticated == false`、`loading == true`，`_Home` 却直接渲染 `_Login`，让正常连接短暂显示云服务说明和禁用的重连按钮。用户要求连接时直接进入聊天列表并显示刷新状态；尚未收到列表结果也不应提示“暂时没有聊天”或要求配置客户端。

锁屏恢复和云服务刷新还会使 `serviceStatus` 暂为 `checking`，从而令 `canConnect` 返回 false。旧设备选择入口把所有不能立即连接的情况都交给安全码弹窗，因此已确认的电脑也反复出现首次连接说明。这个弹窗不能表示服务检查或网络暂不可用。

## Decision

页面拆分后，列表等待和禁用条件继续适用；[手机界面重做](../architecture/2026-11-06-liquid-glass-mobile-ui.md)将切换电脑标签改为保留连接，独立“取消连接”入口承担原返回首页的取消语义。下文的原 `_Home` 和 `_SessionList` 对应新的导航容器与列表页。

`_Home` 对选中电脑且尚在认证等待的状态直接渲染 `_SessionList`，复用顶部的刷新进度。认证后的布局选择仍由屏幕宽度和已选会话决定。列表为空且 `loading` 时不呈现空数据结论；刷新已加载的列表时继续显示当前行，等待响应更新。

聊天列表可见不代表获得认证。未认证时禁用新建聊天、provider 切换、搜索、手动刷新、下拉刷新和会话操作。认证结束后仍未通过时，重新呈现既有云连接恢复入口或直连登录表单；取消连接、云权限撤回和迟到响应继续受 ViewModel 原有代次检查约束。

已登录同一服务器和账号、且有已保存身份核验结果的设备，暂时不可连接时进入列表等待。`CloudViewModel.hasVerifiedIdentity` 先复用当前设备状态，必要时从现有绑定凭据读取安全码；目录仍为 pending 的首次授权设备继续显示确认窗口。身份已保存只决定展示路线，不授予当前访问能力。

`BridgeViewModel.selectComputer` 增加可选 `prepareConnection` 回调，在选中电脑并显示刷新状态后执行。云重连准备等待在途服务检查和设备发现，再用现有 `canConnect` 核对账号、在线状态、服务资格和桌面许可。回调返回后再次核对连接代次与前台状态，才调用业务认证；退出页面或撤回权限后的迟到结果不能发起连接。失败保留既有恢复入口，不回退到首次配对窗口，不替换公钥。该回调是 Flutter 内部的状态编排契约，不修改网络接口、Rust/FFI、凭据或持久化格式。

## Alternatives considered

- 在原设备页等待连接完成可以避免中间登录页，但用户明确要求立即进入聊天列表，因此使用列表自身的刷新状态。
- 单独显示加载页更容易隔离未认证交互，但仍是额外的过渡页面，无法呈现聊天列表的标题、provider 和搜索入口，因此复用现有列表并在未认证阶段禁用操作。
- 刷新时忽略 `canConnect` 的检查中状态能直接尝试连接，但锁屏会使服务资格失效，设备目录也可能正在更新撤销或换钥结果；因此等待现有检查完成，再使用原有条件判定，不以历史安全码替代当前授权。

## Consequences

连接过程直接呈现聊天列表，等待不会被误解为需要重新配对或没有聊天。用户仍须等待真实授权检查、认证与列表读取完成；显示路径变化不缩短网络等待时间。复用全局 `loading` 也意味着已有空列表在刷新时暂时隐藏空状态提示。已保存身份的设备若权限撤回或服务不可用，会呈现失败恢复入口；身份公钥变化继续阻止连接并保留原钥，不能静默信任新钥。真机安装和真实网络连接体验未由组件测试替代。
