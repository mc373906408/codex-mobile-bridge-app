# Agent Note: 聊天导航与输入区使用可读玻璃材质

Status: implemented

## Problem

用户在长聊天滚动截图中指出顶部导航与底部输入区“太透明了”。正文穿过控件后，iOS 的清透材质仍保留明显文字轮廓并产生折射，干扰标题、模型名和草稿阅读。原有无障碍实色降级可以阻止透字，但普通显示模式也需要可读。

## Decision

`BridgeGlass` 提供 `clear` 与 `regular` 两种材质，默认保持 `clear`，聊天详情的顶部栏和输入区明确选择 `regular`。iOS 创建参数传递枚举名称，原生装饰层用对应的官方 `UIGlassEffect`，保持 alpha 为 1；材质变化重新创建 platform view。非原生的 `regular` 使用 18 像素模糊与浅色 90%／深色 88% 的主题底色，压低正文轮廓，同时保留玻璃边缘和背景颜色。减少透明度、高对比度继续优先使用实色。

Flutter 回退将主题底色预混入每个渐变色标。`BoxDecoration` 的颜色和渐变共用画笔，单独调高 `color` 的不透明度不会形成独立底色遮罩；像素回归先暴露了这一点，因此验收实际背景采样，而非只检查配置值。

## 记录归属

[网页布局与玻璃材质](../architecture/2026-11-15-web-client-ui.md)将聊天改为固定标题与分层输入，继续使用本篇的regular玻璃与无障碍实色降级，正文不再与控件争夺同一空间。

已检索活跃记录中的玻璃、透明、导航、输入和无障碍。[原生清透玻璃](../architecture/2026-11-06-native-clear-glass.md)部分重叠：本篇部分取代其所有控件统一使用清透材质的选择，该篇继续持有原生能力检测、装饰层交互隔离和滚动内容叠放。[整体界面](../architecture/2026-11-06-liquid-glass-mobile-ui.md)部分重叠，继续持有导航与视觉布局；[有界更新与悬浮提示](2026-11-06-bounded-chat-updates.md)无关，继续持有数据更新和错误层级。没有完全吸收或应废弃的记录。

## Alternatives considered

- 统一改成实色可以完全阻止透字，但会移除用户已有的玻璃界面，因此仅在无障碍降级时使用。
- 仅调高 Flutter 回退底色改动较少，但当前截图来自原生 UIKit 路径，无法修复用户实际看到的问题。
- 全局替换清透材质可以减少分支，但会同时改变标签和列表操作组；用显式材质参数限定在被指出的聊天顶部栏和输入区。

## Testing

17 项材质及导航回归、12 项聊天视觉及布局回归通过。浅深色像素回归要求 `regular` 红蓝背景差异落在 1–35，`clear` 大于 85，实色降级小于 3；原生通道回归验证实际编码的材质名以及切换后的 view 创建和旧 view 释放。四张浅深色详情／滚动截图已核对并更新；中英文、窄屏、大字号、键盘和草稿导航保持通过。对修改的 Dart 源码与测试执行静态分析无问题。本轮执行定向检查，未重新运行全量测试。

221 个构建输入在锁文件校验和 iOS Debug 模拟器构建前后哈希一致。iPhone 18 Pro / iOS 27.2 覆盖安装后，Runner、原生 Debug dylib 和 Dart 内核哈希与构建包一致，5 个持久化文件在安装后首次启动前逐字节保留，启动返回成功。通过 Device Hub 打开原“了解这项功能”长聊天并滚动，浅色原生材质明显压低背景文字，标题、模型名和输入提示清楚；深色由 Flutter 截图及像素回归验证。证据与含真实会话的截图仅保存在本机 `.tmp/chat-glass-20261115/`。

Android 构建入口因未配置 Android SDK 和 Java 而停止，ADB 也不可用，Lenovo 测试手机未更新；没有为消除交付阻碍卸载或清除手机数据。iPhone 真机安装及原生深色材质尚未验证。

## Consequences

聊天文字控件保留官方玻璃外观，并抑制滚动正文对文字的干扰。代价是 Dart／Swift 需要共同维护材质参数，Flutter 回退增加模糊强度；本轮未进行性能测量。UIKit 与 Flutter 的效果并不逐像素相同，模拟器结果不能替代真机。默认材质及未知原生参数均回退 `clear`，未指定材质的现有调用保持原行为。
