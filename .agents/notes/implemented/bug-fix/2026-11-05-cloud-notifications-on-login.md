# Agent Note: 云账号登录后默认启用通知

Status: implemented

## Problem

桌面收件箱和云连接正常时，手机仍没有云通知。实机仅保留旧联想测试同意，独立的云通知状态未初始化；服务器绑定没有启用推送。当前界面已移除云服务通知面板，独立组件存在但没有可达入口。用户明确要求“登录云服务，云端通知应该是默认打开的，不应该出现开关”。

线上 `/v1/capabilities` 同时报告 U-Push 未配置。这是独立的投递条件，客户端初始化不能替代服务端配置和实际送达验证。

## Decision

App 将当前准确 origin/账号身份和前台状态交给推送控制器。首次登录或恢复已保存登录后，在原生界面允许操作时自动初始化云通知状态；已初始化的状态不重复写入。需要系统通知权限时使用原生权限流程，拒绝后不因定时轮询反复弹窗。自动初始化失败按账号最多尝试六次，账号更换或退出使旧的注册、通知读取和后续权限请求失效。

产品不提供云通知开关，也不恢复此前移除的云服务状态面板。登录页说明默认接收加密通知及推送元数据用途。设备访问仍需桌面明确允许，通知不创建或切换聊天；系统通知权限和原生存储失败继续阻止显示。覆盖安装保留账号、设备、草稿及现有系统权限。

## 记录归属

检索通知、push 和云服务活跃记录后，[云状态边界](../../implemented/bug-fix/2026-11-04-cloud-state-boundaries-and-legacy-removal.md)部分重叠，继续持有权限缩减和迟到结果隔离；[全局架构省察](../../implemented/architecture/2026-11-04-app-architecture-and-scope-audit.md)继续持有各类权限的所有权。两篇的独立手动云通知前提由本篇按用户要求更新；不会把原生撤回能力当作产品开关。[手机交付约定](../../implemented/process/2026-11-05-verified-changes-to-phone.md)持有同签名安装要求。没有完全吸收或需要归档的笔记。

## Alternatives considered

- 把现有开关接回设置页能复用披露组件，但与用户明确的默认开启、无开关要求冲突，因此不采用。
- 仅把展示状态设为开启改动很小，却没有原生持久化、推送登记或服务器投递，无法解决问题，因此走真实原生初始化和既有登记链路。

## Testing

完整 Flutter 测试 315 项通过，2 个需要原生库的套件随后通过 `scripts/test_native.py` 执行，7 项真实 Rust/Flutter FFI 用例全部通过；静态分析无问题。新增中英文窄屏产品导航用例覆盖首次登录和已登录恢复、没有通知开关和额外确认弹窗；控制器回归覆盖未登录、后台、原生不可交互、权限拒绝不重复询问、退出后的迟到响应，以及失败重试上限。原有独立组件测试仍验证内部撤回原语，不代表产品保留开关。

ARM64 debug 构建的 354 个输入文件在构建前后哈希一致，签名和原生包对齐检查通过，服务端 Master Secret 未进入 APK。2026-11-05 12:07:16（UTC+8）覆盖安装到 Lenovo L71091，APK SHA256 为 `da5335ce06fb04fb8f3b4cca7be3d5ddbc1d7ca77727036143570c4421d3f21f`。安装前核对现有 APK 和签名，9 个数据库、凭据及通知文件安装后启动前哈希不变，原始安装时间保留，Activity 正常启动且没有启动崩溃标记。

手机最初锁屏休眠，原生前台条件使默认初始化延后；唤醒后自动保存 `cloud-notifications-v1` 的 accepted 状态，无额外确认。打开现有已授权 Desktop 后，服务器记录有效 U-Push endpoint。将 App 切到后台，只向这台测试手机发送一条通用加密预览；服务器任务 `attempts=1`、`last_code=accepted`、最终 `status=acked`，手机匹配 notification ID 的原生回执已确认，系统 `bridge.events.v1` 通道存在对应通知。没有创建聊天、发送编码任务或操作桌面窗口。

材料位于 `.tmp/cloud-notification-repair-20261105/`。当前测试使用既有 debug 友盟 SDK 同意和服务器测试发送模式，不代表正式签名发布、所有厂商后台、强制停止或 iOS 真机已验收；本次测试覆盖厂商推送→原生解密/系统通知→回执，不是所有真实聊天触发类型的端到端验收。

## Consequences

云账号登录即可初始化云通知，消除缺少可达开关造成的静默关闭；系统权限仍由用户控制。代价是登录恢复需要协调原生前台、持久化和推送登记状态，重试仍有上限，失败不能显示已送达。厂商网络、设备后台限制、失效 token 和服务资格仍可能阻断投递。默认值改变已同步文档和旧测试；正式渠道需要配套发布模式及设备验收。
