# Agent Note: 聊天菜单复用当前快照

Status: implemented

## Problem

聊天详情的「…」在显示菜单前重新向电脑请求会话快照。Codex 的快照读取最近 40 条时间线及元数据，经中继往返或遇到网关等待时，点击后迟迟没有界面反馈。

## Decision

当前选中聊天的快照直接生成菜单。同一连接、账号和完整会话身份继续约束菜单后的操作。选取远端操作后刷新并核验，原生的写前账号和控制状态检查继续执行。复制会话 ID 使用本地已有的 ID。未加载快照的列表项沿用原读取流程。

## 记录归属

[手机界面](../architecture/2026-11-06-liquid-glass-mobile-ui.md)持有入口布局，[原生接入](../architecture/2026-11-10-native-web-parity.md)持有写入和未知结果规则，[菜单标记](2026-11-14-session-activity-indicators.md)持有归档与置顶字段优先级。已检索活跃笔记，三篇均有独立范围。

## Alternatives considered

- 打开前总是请求最新菜单状态能减少新旧状态差异，但会让基本导航依赖每次网络往返。
- 扩充一个专用菜单接口可减少正文传输和解析，但仍需一次请求，现有聊天快照足以绘制菜单。

## Testing

通过延迟快照的 Widget 测试。菜单出现前没有新增快照请求，点击改名后才读取。快照返回其他账号时不打开改名对话框。以本机保存的 40 行聊天样本只读测量，历史读取中位数 11.26 毫秒，已生成的投影分页、路径解析和组包合计约 0.55 毫秒。这次测量未跟踪真实云往返与网关排队时间。

## Consequences

菜单先显示已有状态，远端状态更新则在选操作时生效。点击实际操作仍可能等待网关。已失效的账号或连接需要重新进入聊天。
