# Agent Note: 云目录错误与电脑网关错误分开呈现

Status: implemented

## Problem

模拟器保留云登录后，首页读取云设备目录失败，却同时显示“暂无在线云设备”和“网关连接暂时中断”。目录未读到不能证明电脑离线；底层通用网络错误也不能证明电脑上的网关出错。2026-11-14 本机对官方云 8787 和 18787 的 TCP 连接成功，但 TLS ClientHello 后连接被重置，尚未收到证书或 HTTP 响应。

## Decision

首页目录错误和云服务中心的账号操作错误使用云服务语境的网络、超时和证书提示；电脑连接与聊天继续使用原网关提示。错误分类仍经过现有白名单，未知诊断和凭据不进入界面。目录失败且没有可显示设备时，首页说明目录未能读取、已保存连接仍保留，并提供现有下拉重试提示。

只调整展示，不把网络失败解释为登录失效，不清除凭据、不改变认证、重试或设备访问权限。网络恢复后沿用现有目录同步，成功读取清除目录错误。

## 记录审计

- [响应结束与已恢复错误](2026-11-04-relay-response-completion-and-recovered-errors.md)：部分重叠，本篇限定其通用网关文案在云目录和云服务页的使用；错误白名单、按来源恢复与未知写入保护继续适用。
- [云聊天恢复提案](../../proposed/bug-fix/2026-11-05-cloud-chat-recovery-and-notice-scope.md)：无关，该提案持有聊天订阅和授权恢复，本篇不实现该流程。
- [持久中继](../architecture/2026-11-05-persistent-relay-v2.md)：无关，该篇持有协议与连接生命周期，本篇只有展示变更。
- 已检索活跃笔记的云目录、网络错误与离线提示；没有完全吸收记录或需要废弃的重复提案。

## Alternatives considered

- 全局将“网关”替换为“云服务”改动最少，但会误导直连和聊天错误的处理，因此仅在明确的云请求展示位置选择云语境。
- 读取失败时显示旧云卡片可继续展示保存内容，但会把无法确认的在线状态当作可连接目录；保留既有隐藏规则，准确解释目录失败并保留本地身份。
- 只报告网络诊断无需改 App，但用户仍会把登录后的云请求故障理解成账号失效或电脑离线，因此补齐错误来源和未知状态的展示。

## Testing

六组相关测试共 80 项通过，覆盖中英文云网络错误与网关错误的区别、证书和超时分类、认证错误不被覆盖、诊断不泄露，以及已登录目录失败、凭据和保存连接保留、恢复后卡片重新出现。测试入口为 `error_messages_test.dart`、`error_widget_test.dart`、`cloud_home_online_devices_test.dart`、`cloud_sign_in_widget_test.dart`、`cloud_view_model_test.dart` 和 `cloud_discovery_test.dart`。

`flutter analyze --no-pub` 无问题；Xcode Debug 构建完成，覆盖安装并启动于 iPhone 18 Pro / iOS 27.2 模拟器。应用继续运行且原登录仍可进入云电脑。Android 构建入口因本机未配置 `ANDROID_HOME` 和 `JAVA_HOME` 中止，ADB 也不可用，未更新 Lenovo 真机。笔记树、格式与归档校验通过；交付与网络诊断证据保留于 `.tmp/cloud-connection-20261114/`。

本机原网络路径对官方云 8787/18787 在 TLS ClientHello 后重置；系统 Shadowrocket 从未连接变为已连接后，同一公开能力接口返回 HTTP 200，TLS 校验通过，旧 App 随既有自动重试恢复 Desktop 在线卡片。此恢复发生在安装文案修正前，证明本次故障涉及网络路径，不能归功于文案修改，也不能据此断言具体哪个中间设备阻断了连接。诊断过程没有切换系统网络、退出账号或重新登录。

## Consequences

用户可区分云目录不可读与电脑离线，且网关、账号认证和本地存储错误仍保留自身含义。代价是展示层维护两种传输错误语境，新入口必须明确错误来自云账号/目录还是电脑连接。此修复不改善不可达的网络路径，也不代表已验证发送、审批或真实手机连接。
