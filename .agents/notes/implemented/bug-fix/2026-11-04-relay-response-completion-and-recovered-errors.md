# Agent Note: 中继响应结束与已恢复错误提示

Status: implemented

[持久中继 v2](../architecture/2026-11-05-persistent-relay-v2.md)将单请求通道替换为复用会话；已认证结束标记、截断拒绝和按错误来源清理的原则仍适用。

## Problem

用户在已加载聊天列表的手机页面持续看到“无法连接网关，或安全证书不受信任”。该文案由统一 Network 错误映射产生，不能证明证书校验失败。旧列表刷新成功不清除旧网络错误，恢复后的实时 snapshot 也不清除其旧订阅错误。隔离测试另已复现：手机每收到正文就回发 credit，若补充 credit 写失败，即使后续正文和已认证 response_end 已到达，旧代码也会在读取前中止，把完整响应判为失败。

## Decision

`receive_response_body` 以已认证 response_end 为完成依据。初始授权、请求提交和首个 credit 仍须成功；正文接收阶段，补充 credit 写失败后停止重复写 credit，继续读取已经到达的记录，只在完整结束标记通过后成功，缺失结束、截断、认证失败和超限仍失败，不重发业务请求。真实 WebSocket/Noise 半关闭测试覆盖该边界，核心协议和证书核验不变。

列表刷新、订阅、待核实创建读取和前台重连分别持有各自错误的版本号，成功时只清除本操作此前记录且仍展示的错误，不覆盖其他失败（尤其未知写入、草稿或附件）。所有 error 赋值递增版本，旧读取结果仍受连接/选择代次保护，读取创建记录后再次确认连接仍当前。通用网络文案改为“网关连接暂时中断，请检查网络和电脑上的网关服务”；独立 TLS 错误继续提示证书核验失败，不降低证书检查。

## Alternatives considered

- 只改网络错误文案更简单，但既不能清除已恢复的旧提示，也不能纠正完整响应被判失败。
- 每次任何读取成功都清空全局错误能消除横幅，但会掩盖其他仍待处理的写入/草稿错误，因此按错误版本和操作来源清除。
- 忽略所有正文接收异常会掩盖截断，因此只有收到并认证结束标记才算完成，credit 写失败本身不决定已经传完的响应结果。

## Consequences

完整响应不再因附加 credit 写失败被误丢弃，成功恢复的只读操作也不再留下自己的旧横幅。链路实际损坏时仍需等待读失败或既有超时；没有完成标记时仍拒绝成功。通用 Network 映射仍可能包含无法进一步分类的传输错误，移除推测证书的文案不等于证明所有底层错误都已细分。未捕获用户每一次真实失败的完整请求轨迹，因此不把隔离复现或启动成功等同于真实账号链路永不出错；没有写入真实聊天或代用户重试未知操作。

后续用户报告退出重登后仍失败，完整 Go Hub＋Python Connector＋此 Rust DLL/Dart Repository 联调确认还存在桌面发送 response_end 后立即外层 Close 的另一竞态。桌面仓库的 `2026-11-04-cloud-response-peer-close.md` 持有修复：有界等待接收方关闭；四轮退出重登/32次列表和真实手机连续刷新通过。此结果补充本篇分层验证的缺口，没有改变手机接收端对完整/截断响应的判断。
