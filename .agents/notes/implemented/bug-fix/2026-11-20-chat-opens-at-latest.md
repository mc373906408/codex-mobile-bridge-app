# Agent Note: 打开会话先显示最新消息

Status: implemented

## Problem

用户重新打开会话时看到历史中段，希望像即时通讯软件一样先看到最近消息。原实现从 `readingPositions` 恢复像素偏移，甚至会为寻找上次的锚点自动读取更早历史。即使不恢复偏移，正向懒加载列表也只估算尚未测量的可变高度消息，首帧跳到估算终点不能保证看到最新一条。

## Decision

每次进入会话都从最新一页的末尾布局，不再写入、恢复旧阅读坐标，也不为恢复坐标请求历史。旧偏好不参与读取，不做数据库迁移。最新一页和历史分页仍由既有鉴权和会话读取链路提供，数据保持时间正序。

时间线以初次呈现的最后一个消息行作为分界，较旧内容向上、新消息和运行提示向下懒加载。贴底且未滚动时，视口跟随实际布局出的底部；离开底部时，新消息不移动分界上方正在阅读的内容。原来的「更早的消息」按钮由[滚动触发分页](../feature/2026-11-20-scroll-to-load-chat-history.md)取代。同一会话内切换工作台不丢失已挂载的位置。会话重开、账号或历史代次变化、原分界行不再存在时，从当前最新内容重新定位。

## 记录归属

[原生业务接入](../architecture/2026-11-10-native-web-parity.md)的跨次阅读位置恢复由本篇取代，工作台、已读和引用的身份边界不变。[有界更新](2026-11-06-bounded-chat-updates.md)仍持有网络分页和实时读取，[活动摘要](../feature/2026-11-15-chat-activity-summary.md)仍持有分组和动效。[会话菜单延迟](2026-11-20-chat-menu-latency.md)和[图片缓存](2026-11-20-chat-image-cache-and-preview.md)分别持有菜单读取和附件加载，与正文首屏不同。未发现完全吸收或需要废弃的记录。

## Alternatives considered

- 只删除坐标恢复，仍使用正向列表并在布局后跳到末尾。实现短，但不等高行的尺寸尚未测量，手机与宽屏的长会话夹具都无法保证落到最新一条。
- 用单个倒序列表。它天然从最底部创建消息，手动加载旧页也稳定；但在头部插入新的尾部消息时，即使用消息键重映射，回归夹具中的旧消息仍偏移了 170 个逻辑像素。使用分界两侧的惰性列表隔离这两种增长。
- 用本地最近消息缓存做即时进入。它能覆盖弱网下的复访等待，但需要增加正文存储、失效和身份隔离；此次只改变定位，不引入本地消息副本或缓存驱动的权限状态。

## Testing

`test/ui_surface_layout_test.dart` 在 390 和 1024 逻辑像素宽度从列表打开 40 条不等高消息，注入旧阅读坐标及可分页历史，验证收到最新快照后的第一帧即可点击最新消息、重开仍贴底且没有自动历史请求。另验证手动分页、实时尾部追加、短会话的滚动范围以及工作台切换。活动详情展开沿用既有回归。

`flutter test --no-pub` 全量 565 项通过、5 项按条件跳过，`flutter analyze --no-pub` 无问题。浅色和深色的会话、滚动、活动与重连截图逐一核对后更新。iPhone 18 Pro 模拟器原位安装后，启动前的数据库及云元数据哈希与安装前一致，安装二进制与构建输出一致，应用成功启动；没有以模拟器启动代替真机交付或线上延迟测试。

## Consequences

重新打开不再回到上次阅读的段落，也不等待旧页；用户仍可向上查找。没有可复用数据时，第一条正文仍需等待网关首个快照；[会话列表预读](../feature/2026-11-20-chat-list-prefetch.md)缩短预读命中时的等待，不改变本篇的滚动定位。两个改动均没有测量线上真机点击到可见的总耗时。
