# Agent Note: 聊天附件按会话缓存并渐进预览

Status: implemented

## Problem

聊天正文和图片独立加载，但每个图片组件只持有自己的读取 Future。进入同一聊天或组件回收后再次出现，仍下载同一份图片。此前列表对上传附件固定读取原图，手机收完整份数据才缩小解码；点开预览后又等更大尺寸解码，已显示的小图没有用作首帧。

## Decision

Rust 从聊天附件元信息读取已有的 `thumb` 提示；有缩略图的上传附件走既有 `variant=thumb` 路由，放大才读原图。没有提示、只有桌面原文件或旧网关没有缩略图时，直接读一次原图，列表在本地缩小解码。直连收到 `X-Preview-Variant: fallback-original` 时也复用收到的原图；云中继不透传这个头，提示存在但响应无法辨别时不把收到的内容冒认为原图。不新增网关路由、网络权限、上传操作或草稿字段。

Flutter 按会话完整身份（电脑、客户端入口、执行环境及会话）、账号、历史版本、连接代次、来源、附件 ID 和图片版本复用内存字节，合并同版本并发读取。返回列表不清缓存；上限为 32 MiB、64 项，单项命中期五分钟，命中不续期。没有账号身份时不缓存；认证丢失、连接代次变化（含进入后台）、当前聊天账号或历史版本变化、重置和内存压力清除缓存。不同账号或历史重新打开同一会话时，清除该会话的旧项。清除后迟到的读取不能写回。缓存只用于已打开的认证快照展示，不能替代聊天快照或任何写入权限核验。

预览首帧复用列表解码的小图，在高清首帧可用时替换，不重置缩放。高清读取失败仍保留小图并提供重试；失去原读取身份后不再显示旧预览或接受其迟到结果。用户尚未上传的本地图片不触发网关读取，缩略图、编辑和提交时序由[本地图片预处理](2026-11-20-local-chat-photo-preparation.md)持有。

## 记录归属

检索图片、附件、缩略图和时间线后，[聊天活动摘要](../feature/2026-11-15-chat-activity-summary.md)继续决定工具详情何时挂载，本篇持有挂载后的资源读取和预览。[有界聊天更新](2026-11-06-bounded-chat-updates.md)继续持有分页，[最新消息首屏](2026-11-20-chat-opens-at-latest.md)持有阅读位置，[原生业务接入](../architecture/2026-11-10-native-web-parity.md)的只读及身份边界不变。[手机交付流程](../process/2026-11-05-verified-changes-to-phone.md)独立适用。未发现需要废弃的图片缓存提案。

## Alternatives considered

- 在手机写入持久图片缓存，重启后仍能命中；但需要定义聊天附件在设备上的持久保留和清理规则，也会让可替换的桌面路径更容易长期显示旧内容，本次仅保留有界内存缓存。
- 网关为所有桌面原生历史图生成缩略图，可进一步减少首次传输；但需要同步部署网关，新增桌面文件处理和缩略图失效规则。手机优先复用现有缩略图协议，旧网关仍可正常展示。
- 点开即等待高清完成，组件更少；慢链路下会让已看见小图的用户再次面对空白，采用小图先显示、高清再替换。

## Consequences

在缓存未过期且未淘汰的同一前台会话中，不需要重复下载图片；有网关缩略图时列表不先拉原图。只有原文件的记录首次仍要接收完整图片，重启或缓存清除后仍需读取。32 MiB 约束缓存保留的编码字节，并非 Flutter 显示期间的总内存上限。聊天正文首屏和分页路径不变，本次没有以合成测试推断真机耗时。
