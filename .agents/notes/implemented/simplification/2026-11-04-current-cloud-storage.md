# Agent Note: 未上线 App 直接使用当前连接和凭据格式

Status: implemented

## Problem

[云状态修复](../bug-fix/2026-11-04-cloud-state-boundaries-and-legacy-removal.md) 已删除手动配对 API，但仍有旧字段读取迁移和旧 SQLite 连接表转换。用户明确尚未上线，旧数据库和已有绑定无需保留；继续接受缺省字段会掩盖过期测试夹具和混用旧客户端的问题。

## Decision

新 SQLite 直接建立 schema v3 的 direct/relay 连接表及其索引，不创建旧表后再复制迁移。只有空的未版本化数据库和当前版本可以打开；其他结构明确拒绝，不自动删除文件或覆盖记录。当前版本的草稿、未知写入和账号范围在重启后继续保留。

云绑定凭据要求完整的当前字段，旧 `request_attempted` 不再读取或迁移，缺少当前字段及未知字段均拒绝。Computer JSON 必须显式声明连接类型；Dart 新建直连对象的默认参数仍是界面 API 的便利行为。真实 FFI 夹具使用当前格式，旧格式拒绝由 Rust 边界测试单独覆盖。

## 记录归属

[原生 Web 功能接入](../architecture/2026-11-10-native-web-parity.md)部分取代本篇“只接受 v3”的版本边界：现有手机从 v3/v4 事务升级至 v5，保留草稿、连接和未知操作；早期开发格式仍拒绝，不改变本篇云凭据完整字段要求。

本篇部分取代云状态修复中的旧字段迁移决定，双方互链；不改变只读重新核验、通知撤回或创建记录的账号隔离。全局[架构省察](../architecture/2026-11-04-app-architecture-and-scope-audit.md)继续持有 A1–A6 的原始发现与当前处置状态。本仓没有其他存储兼容提案。

## Alternatives considered

- 继续把旧连接视为 direct 并移除旧字段，可以保留开发安装数据；但用户明确不需要迁移，而且会隐藏过期的凭据格式，因此删除。
- 打开失败时自动清库能让应用立即重新运行，但也会删除当前无法识别的草稿或操作证据，因此只报错并要求初始化独立的新存储。

## Consequences

连接类型和云凭据的格式边界明确，测试不再依赖已退役字段。代价是旧开发安装需要重建本地存储与云身份。这个决定不允许在切换账号时删除当前格式的未知写入，也不改变现行连接关闭后保留密钥的恢复规则。首次正式发布后若需要跨版本数据保留，必须另定升级契约。

## Testing

Rust 覆盖旧/未来版本及非空未版本化数据库拒绝，拒绝后原连接仍在；当前库可重开，同 origin 多个 relay 及账号/固定公钥不能替换。完整凭据、真实 Rust FFI、Flutter、Android 与构建快照的结果随本批修复保存于本机 `D:/github/.codex-tools/architecture-closeout-20261104/`。Windows 不提供 Swift/Xcode、签名设备或真实厂商送达验证。

后续[手机部署](../process/2026-11-04-current-schema-phone-deployment.md)确认 Lenovo 开发安装仍是 v2，在用户已授权丢弃旧开发数据的范围内覆盖安装后清理目标 App，实测新启动建立 v3。该一次性部署清理不改变运行时代码对未知格式拒绝且不自动删除的规则。
