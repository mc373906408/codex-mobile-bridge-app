# Agent Note: 电脑配置归电脑端

Status: implemented

## Problem

手机设置有一套客户端、编码账号、WSL、通知渠道、文件传输和网络管理页面。电脑端已有配置入口，两端重复维护控件和管理调用。用户只需要在电脑端配置这些功能。

## Decision

移除手机「电脑功能与设置」的入口、子页、独立显示开关和对应的 Rust/FFI 管理命令。App 设置提供外观、云连接和手机通知偏好。聊天继续读取电脑提供的实例、项目和模型目录。项目写入继续校验编码账号版本、客户端实例和网关身份。

项目操作的结果待核对记录由「新建聊天」按需显示。记录沿用原作用域，用户在电脑上确认结果后可标记已核对。历史管理操作仍保存在 SQLite。项目审核列表只查询目录、登记及工作区授权操作。

## 记录归属

[原生 Web 功能接入](../architecture/2026-11-10-native-web-parity.md)的手机电脑管理范围由本篇接管，保留其项目身份、会话能力和写入规则。[多主机通知](../bug-fix/2026-11-18-multi-host-notifications.md)持有本机的通知偏好与授权约束。[手机交付](../process/2026-11-05-verified-changes-to-phone.md)继续适用。活跃笔记中无整篇重复或待退役提案。

## Alternatives considered

- 隐藏设置入口能快速缩小页面，但仍会保留账号和网关管理调用，后续还需维护这些分支及测试。
- 继续在手机提供远程管理能支持离开电脑时改配置，但会重复电脑已有的配置流程，也偏离用户给出的职责划分。

## Testing

`flutter analyze` 通过。Flutter 全量 541 项通过、5 项条件跳过，Rust 91 项通过、1 项忽略。真实 FFI 11 项及实际桌面 HTTP 契约 1 项通过。界面回归覆盖连接电脑后的设置页和项目操作核对，存储回归验证旧编码账号记录过滤和实例隔离。

iOS 0.2.0 自签 IPA 完成打包和完整性验证。iPhone 18 Pro 模拟器覆盖安装并启动，安装包二进制与 Flutter 内核匹配，启动前数据库摘要一致。本机缺少真机签名身份，iPhone 真机尚未安装。

## Consequences

手机设置页更短，PC 是电脑配置的入口。需要修改电脑配置时须使用电脑端。手机端新建聊天可以核对同一作用域下的未确认项目操作，原操作记录继续用于拒绝重复提交。
