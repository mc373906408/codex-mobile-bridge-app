# Agent Note: 苹果风格界面与独立标签导航

Status: implemented

## Problem

原界面把首页、连接、会话、聊天和设置集中在一个 Material 页面中，返回首页同时清理业务选择。用户要求整体改为苹果原生 Liquid Glass 方向，并确认电脑、聊天、设置三个标签、系统蓝和适合长内容的聊天排版。标签切换必须独立于连接和草稿生命周期。

## Decision

材质后续修正由[原生清透玻璃](2026-11-06-native-clear-glass.md)持有：支持的 iOS 版本使用官方 UIKit 材质，其余平台使用更透明的 Flutter 回退，内容实际延伸到控件下方。本篇继续持有独立标签导航，原“全部 Flutter 自绘”的限制由后续决定取代。

Flutter 继续持有界面，现有 ViewModel、Rust 和存储继续持有业务。设计组件集中管理动态颜色、材质、排版和无障碍；玻璃只用于导航、标签和输入工具区。UI 导航控制器持有标签，切换标签不调用断开、返回电脑或重新连接。显式切换电脑、删除、退出账号仍使用既有校验与草稿保存。窄屏聊天详情隐藏标签，840 逻辑像素以上且正文缩放小于 1.6 时双栏。

同一已授权且已认证或连接中的电脑仅切回聊天标签；实际授权条件仍先检查。等待中的连接有独立取消入口，调用原有返回电脑流程使迟到响应失效。标签切换保留订阅，前后台恢复仍按现有业务规则重新认证。未显示标签的动画通过 TickerMode 暂停，避免隐藏进度条持续产生帧。列表位置使用 PageStorage，短屏和大字体下列表头与列表一起滚动；聊天输入行数依据实际布局高度收缩，保留内部文本滚动。

iOS 的只读无障碍通道提供减少透明度并观察变化，失败时使用实色；不扩大现有通知通道。普通输入、返回、选择继续使用当前平台行为。

## Alternatives considered

- 仅更换 Material 主题容易控制改动，但不能达到用户确认的导航和页面重做目标。
- 完整改用 SwiftUI 可以直接使用苹果系统材质，但无法覆盖现有 Android 产品，且会重复业务适配；使用共享 Flutter 组件。
- 直接以业务的 computer/selected 决定首页能复用旧代码，但切换标签会清理上下文；增加独立 UI 导航状态。
- 每条内容卡片使用玻璃能突出效果，但增加长列表渲染成本并削弱文字层级；正文使用标准材质。

## Consequences

视觉和交互统一，标签切换保留工作上下文；页面从 app.dart 拆出，公共样式集中维护。Flutter 自绘材质不等同于苹果系统渲染器，保持安卓和 iOS 共享代码的代价是需要维护材质、手势及无障碍回归。透明层仍产生 GPU 成本，因此不逐行模糊，系统要求时回退实色。截图字体固定用于稳定回归，实际设备仍使用系统字体。Windows 本机无法运行 Xcode，GitHub CLI 未登录且无已配置 macOS 执行环境，iOS 原生编译和真机验证仍存在缺口。
