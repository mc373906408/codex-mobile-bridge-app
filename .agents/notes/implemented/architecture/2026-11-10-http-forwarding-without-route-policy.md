# Agent Note: App 传输层取消接口和方法清单

Status: implemented

## Problem

用户要求全部链路删除逐接口白名单、黑名单。桌面转发取消清单后，App Rust 加密传输仍拒绝 GET/POST 之外的方法，直连也未完整传递这些方法的正文，造成同一业务在不同通道行为不同。

## Decision

Rust relay 取消方法集合检查，直连和 Noise/P2P 使用同一正文规范：POST 缺省正文仍为 `{}`，其他方法缺省为空；GET/HEAD 禁止非空正文，所有正文保持 20 MiB 上限。直连非 GET/HEAD 请求仍携带已有 CSRF，未知写入继续使用持久记录且不自动重放。

接口是否存在、实例能力和当次权限由网关 HTTP 处理器判断。App 业务层仍使用结构化操作和完整身份，页面不获得任意 URL、凭据或原生 IPC 调用能力。配对密钥、账号归属、撤销、重定向限制、文件边界与报文校验继续生效；云账号页面继续只提供登录和现有登录态管理。

## 记录审计

- [原生 Web 接入](2026-11-10-native-web-parity.md)：部分重叠，本篇取代其中通道接口清单的验收要求，保留完整身份、存储和业务能力规则。
- [架构省察](2026-11-04-app-architecture-and-scope-audit.md)：部分重叠，继续保留认证、被动读取和未知写入边界。
- 已检索活跃笔记，没有完全重复或失效提案；错误文本过滤、原生 IPC 分派和 P2P 引导配置不属于逐接口策略。

## Alternatives considered

- 继续补充各通道的接口表能局部解锁功能，但需要反复维护且已经造成遗漏，用户明确要求删除。
- 使用接口黑名单仍在传输层复制业务授权，不能满足删除整套功能的要求。

## Testing

新增真实直连 HTTP 测试，核对非 GET/HEAD 请求正文及 CSRF。新增成对 Noise 密钥和回环 WebSocket 测试，验证未来接口的 POST/PUT/PATCH/DELETE/HEAD/OPTIONS 原样传递与响应确认。夹具必须使用对应的控制和预览公私钥，认证失败不能被跳过。实际执行、FFI 与同签名手机安装结果记录在[验收矩阵](../../../../docs/web-parity.md)。

本轮 Rust 81 项通过、1 项专用 P2P 夹具跳过，Clippy 通过；实际 DLL 的 FFI 8 项及配套桌面工作树 HTTP 契约 1 项通过。ARM64 APK 的 12 个 ELF 库打包检查通过，Lenovo L71091 同签名覆盖安装、设备 APK 哈希和冷启动核对通过；首次启动前 38 个数据库/WAL/偏好文件逐字节保留，首次安装时间未变。构建产物、私有备份与安装日志留在忽略目录，不提交凭据或用户数据。

远端 `http-forwarding-20261110-d35a7a5` 已按用户授权部署，公网 TLS、健康、认证和跨 Origin 拒绝核验通过。手机刷新后保留云登录和原电脑，重新连接并读取真实 Codex 列表、电脑功能页、已保存账号页成功，未再遇到接口策略拒绝；账号额度、实际切换和完整传输组合仍按矩阵待验。

## Consequences

新增业务无需再扩展传输方法集合；HTTP 处理器必须完整校验权限。保留旧草稿、账号、连接及未知操作，不因协议调整清库。Android、iOS 共用此 Rust 实现，但 Windows 上的源码与 Android 验证不能代替 iOS 构建、签名和设备证据。
