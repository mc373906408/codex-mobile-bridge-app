# Agent Note: 后续 App 修改同步更新测试手机

Status: implemented

## Problem

源码修复和组件测试完成后，用户的手机仍运行旧包，无法体验本轮连接列表与重复配对弹窗修复。用户于 2026-11-05 明确要求“后面所有改动都要更新到手机”，将手机交付纳入后续修改的完成条件。

## Decision

每轮影响 App 的修改完成必要验证后，同轮构建并覆盖更新已确认的测试手机，不再等待单独安装指令。当前目标为 Lenovo L71091、Android 13、ARM64，包名 `dev.waken.bridge_mobile`；每次安装重新核对设备身份、现有 APK 签名及源码快照，沿用兼容签名，安装后核对 APK SHA256、启动结果及安装期间的数据保留。正常更新不执行卸载、清库或真实账号退出；手机不可达时保留构建产物并明确报告尚未安装，不将源码完成等同于手机已更新。

此约定通过仓库根 [AGENTS.md](../../../../AGENTS.md)约束后续工作，不能用于发布到商店、自动登录真实账号、授予新设备权限或擅自提交聊天。连接等待修复仍由[连接列表与设备重连](../bug-fix/2026-11-05-connecting-conversation-list.md)持有。

[2026-11-06 手机界面重做](../architecture/2026-11-06-liquid-glass-mobile-ui.md)沿用本篇同签名覆盖更新及数据保留要求。

检索手机、部署、签名及发布记录后：[当前存储手机部署](2026-11-04-current-schema-phone-deployment.md)部分重叠，保留一次性 v2 清理的原因；该决定不适用于后续普通覆盖更新。[GitHub 发布](2026-11-04-github-mobile-release.md)持有正式签名及下载分发，与测试手机安装是不同交付路径，两篇互链。本篇新增持续交付到测试手机的要求，不改写上述决定；没有完全吸收记录或过时提案。

## Alternatives considered

- 每次修改只交源码、等用户再次要求安装，能让用户单独选择更新时间，但已不符合本次明确的后续交付要求。
- 默认通过公开 Release 交付有固定下载入口，但当前手机使用独立开发签名，公开发布也不是每轮测试的必要条件，因此沿用同签名覆盖安装。

## Testing

本轮构建包含通过 307 项 Flutter 测试的连接列表与重连修改，353 个源码/配置文件构建前后哈希不变，原生库对齐、签名和服务端秘密排除检查通过。2026-11-05 10:31:49（UTC+8）覆盖安装成功，手机 APK SHA256 与构建包同为 `1ff0c9ba95a48a52bb8ed8023be7a10633a9d59cdadc4171f7df77f639a348b7`。原始安装时间保留；9 个数据库、凭据及通知配置文件在安装后启动前哈希一致。Activity 返回 ok，进程运行正常，未发现启动崩溃或原生库加载错误。

真机选择已授权 Desktop 后捕获到聊天列表刷新状态，连接后显示列表且没有安全码或云连接说明页面。刷新与返回桌面后重新打开的页面检查均保持聊天列表且没有配对窗口；刷新第一次采样未读到完整列表，按实时控件位置重新刷新并等待后确认通过，原始采样留存。没有进入聊天、发送消息、重新配对或退出真实账号；未执行物理锁屏解锁。证据位于 `.tmp/connection-list-refresh-20261105/`，任务专用 ADB 5038 在完成后停止。

## Consequences

用户在同轮获得实际可用的手机更新；每轮修改都需要构建和手机在线，交付时间增加。手机签名变更、授权丢失或网络不可达会阻止安装，不能通过卸载、重置数据或绕过授权消除这些阻碍。启动成功只证明包可启动，真实云链路体验需另行核验。
