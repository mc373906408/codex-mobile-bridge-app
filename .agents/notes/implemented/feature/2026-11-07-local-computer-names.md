# Agent Note: 本地设备名称与精简电脑卡片

Status: implemented

## Problem

用户要求聊天标题直接显示设备名，在“我的电脑”自定义名称，并移除卡片上 P2P、云服务来源及连接许可等重复技术信息。现有 Computer 的值相等比较包含 name，业务回调据完整对象判断迟到响应，因此重命名不能直接替换正在连接的 Computer 对象。

## Decision

显示名称独立于业务 Computer，使用 FlutterSecureStorage 的新偏好键 `bridge.computer_names.v1` 保存 JSON 映射。键包含连接 ID、类型、地址，以及云连接的服务器、账号、网关、绑定和已确认公钥，名称不会串到另一账号、服务器或设备身份。Rust/FFI、原数据库格式、设备凭据及桌面名称均不改变。

BridgeViewModel 统一解析显示名，电脑卡片、已保存列表、聊天标题、登录恢复和设备弹窗使用相同入口。名称保存成功后才更新显示；保存失败保留已确认的名称，并在重命名弹窗提示重试。保存期间拒绝第二次重命名，删除直连时清理其别名；重启和目录刷新不会覆盖别名。偏好读取失败不阻断既有连接初始化，重命名前重新读取，不能用空映射覆盖未读出的名称。

电脑卡片只展示设备名和在线/连接状态，通过“⋯”菜单或长按修改名称。云设备列表的可见性与点击后的身份/许可流程保持现有规则，常规卡片不显示路径、P2P、服务器来源或授权细节。聊天页只显示设备名标题，长名称最多两行，完整名称通过提示与可访问性文本提供，大字号下操作组换行。

## 记录归属

检索活跃记录中的重命名、设备名称、偏好、卡片与身份边界后，[手机界面](../architecture/2026-11-06-liquid-glass-mobile-ui.md)部分重叠，继续持有布局和独立导航；[架构省察](../architecture/2026-11-04-app-architecture-and-scope-audit.md)部分重叠，继续持有权限、连接与未知写入；[当前存储格式](../simplification/2026-11-04-current-cloud-storage.md)无关，本次不改变其数据库版本决定。没有同一别名机制的旧决定，没有完全吸收或需要归档的记录。

## Alternatives considered

- 直接覆盖 Computer.name 可以复用现有保存接口，但 name 参与运行时对象相等判断，云发现与连接恢复可能拿到不同对象；只覆盖展示名，避免触碰连接身份与草稿生命周期。
- 在服务器或系统中重命名能同步到其他客户端，但用户指定的是 App 中“我的电脑”的名称，不应隐式更改远端主机或账户目录；本轮使用本地偏好。
- 仅长按提供重命名最省空间，但入口不易发现；同时提供明确的“⋯”菜单。

## Testing

`flutter analyze --no-pub` 无问题，完整 Flutter 回归 377 项通过、2 项原生库入口按既有条件跳过。新增用例检查独立 repository 的名称读写、账号/服务器/公钥隔离、重新加载目录、保存失败与并发保存、删除直连只清理对应别名、重命名后连接和草稿不变、中英文窄屏操作、长名称在 320 宽度的 1/2 倍字号布局。云端列表仍只显示当前可见设备，未授权设备卡片不显示技术状态，点击后的授权规则仍通过既有回归。

浅深色电脑页、聊天标题、智能体菜单和重命名弹窗基线已核对；中文合成预览包含直连与在线云端设备，保存在忽略目录 `.local/device-name-delivery/`。预览不是 iPhone 真机或 APNs 验收，安装事实按构建后的实际结果记录。

## Consequences

常用页面突出用户识别的设备名，改名不会建立连接或重放操作。名称只在当前 App 生效，不跨手机同步；如果本地偏好被清除，需要重新命名。共享组或网络认证均不依赖这份展示偏好，卡片精简也不表示放宽访问权限。
