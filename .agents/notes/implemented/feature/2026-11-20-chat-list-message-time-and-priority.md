# Agent Note: 聊天列表显示消息时间并优先预读活跃会话

Status: implemented

## Problem

聊天列表只有电脑与项目名称，用户无法辨别最后一条消息是哪时发来的。预读也只覆盖列表首条，置顶的已读会话会占用这个机会，而未读、运行中的会话排在后面时仍要从点击后才开始读取。

## Decision

列表副标题在电脑和项目旁显示最新一条用户或助手消息的时间，使用已授权的最新页或既有预读结果中的 `timestamp`，按手机时区和语言格式化。工具记录不算聊天消息；最新一条没有时间时，不借用前一条的时间。只拿到列表的 `updatedAt` 或 Codex 原生 `updated_at_ms`、`updated_at` 时，用会话更新时间兜底。副标题只显示时间或日期，提示文本区分消息时间与会话更新时间；两者都没有就不显示时间。显示不新增逐行请求，也不假造 iPhone 接收回执。会话版本变化、身份失效及内存清理后，旧消息时间不继续充当当前值。Codex 列表缺少驼峰版本字段时，已读校验和预读命中用原生列表版本而不是空值。

前台列表绘出后，从已加载、未折叠的条目中优先选运行中，其次选观察到新终态未读的会话，再选其他未读，组内沿用列表顺序。已读且空闲的不预读；等待读取身份的现版已读标记不通过预读重复核对。关闭活动点的显示选项不关闭优先级信号。每个列表代次至多尝试 8 个会话，其中普通未读最多 4 个，为稍后返回的活跃状态留预算。同一时刻最多一项推测请求，同一候选在本轮不重复，当前版本已有预览则跳过。每个会话仍只读最近一页，最多 40 条；预读不翻旧页，不订阅、不激活、不标已读。

## 记录归属

[会话列表预读](2026-11-20-chat-list-prefetch.md)的首条候选规则由本篇取代，保留并发合并、内存容量、认证和操作边界。[列表活动提醒](../bug-fix/2026-11-14-session-activity-indicators.md)继续持有活动轮询与未读终态；[原生业务接入](../architecture/2026-11-10-native-web-parity.md)继续持有已读核验与账号隔离。[翻阅历史自动加载](2026-11-20-scroll-to-load-chat-history.md)属于打开后的历史分页，不增加预读页数。模型或图片缓存与此处无重叠，没有需要归档的记录。

## Alternatives considered

- 直接显示列表更新时间，能在首帧覆盖所有返回更新时间的条目，但改名等元数据操作也会更新时间；有证据时优先显示真实消息时间，更新时间仅作兜底。
- 增加桌面端批量读取真实消息时间，可为从未打开的所有行提供精确值，但需要为多个原生提供方建立消息时间索引或读取历史。本次沿用既有快照和列表，不增加桌面部署和逐行网络读取。
- 并发预读全部未读及运行中，可以更快填满缓存，但未读可能覆盖整页，会与显式打开、活动查询及中继竞争。保留单在途，并为活动候选保留总预算。

## Testing

`test/session_prefetch_test.dart` 覆盖先请求运行中、随后读取未读、已读空闲不进入队列、活动轮询后使用保留预算、单在途与复用；`test/session_list_time_test.dart` 覆盖秒和毫秒、ISO 字符串、缺失时间、过滤工具记录，以及 320 像素宽和中英文两倍字号时正常显示无前缀的时间，预读结果替换更新时间时没有新增网络读取。

本轮定向测试 93 项通过，全量 Flutter 603 项通过、5 项按条件跳过，静态分析无问题。浅色和深色的会话列表及客户端菜单截图已核对。iPhone 18 Pro 模拟器覆盖安装后启动成功，安装的二进制与本轮构建一致，启动前数据库及现有云配置哈希不变；未验证真机和实际云链路。

## Consequences

同一屏可以预读多个更可能被打开的会话，不会修改列表排序。列表更新时间已知但消息时间未知时仍是估计线索，不代表设备收到消息。未读超过预算、折叠组和未加载分页按原路径打开；命中率和真实网络首帧仍未测量，不以合成请求次数推断线上耗时。
