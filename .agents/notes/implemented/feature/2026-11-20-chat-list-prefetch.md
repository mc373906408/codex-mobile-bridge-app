# Agent Note: 会话列表预读最近消息

Status: implemented

## Problem

会话已能在首批数据到达后从最新消息布局，但用户从列表点开尚未读过的会话时，网关读取仍从点击后才开始。只在退出时缓存内容无法缩短首次打开的等待。列表入口还会为自动标记已读再次读取快照，即使该次打开已经取得了可验证的身份。

## Decision

前台已认证的聊天列表在绘出后，在没有打开会话、搜索或归档过滤时预读非折叠候选。[运行中和未读优先](2026-11-20-chat-list-message-time-and-priority.md)取代原来的只预读列表首条。每个列表代次和候选会话最多尝试一次，同时最多一项推测预读。预读走现有认证快照接口，只取最近页；不激活会话、不订阅、不取旧页或附件、不标记已读。手动打开同一会话可复用该连接和列表代次下尚在途的读取；失败则按正常前台路径重新读取一次。后台预读失败不展示错误。

已完成的预读或正常快照只保存展示用的最近消息，在本次已认证连接内供重进使用。每页最多 40 条、128 Ki 个 UTF-16 码元，最多保留 8 个会话，读取不延长两分钟的复用期限。缓存按完整会话标识查找，记录上次核验的账号与历史代次，不持久化，不保留附件句柄、分页游标、控制令牌或审批状态。预览期间标记「正在同步」，只显示正文，页面操作仍等待真实快照。首个读取失败即撤下预览；认证状态或连接代次变化、已知中继断开、内存压力清除预览及在途复用资格。收到不同账号、历史代次或重置时不合并旧内容；桌面尚未告知的变更无法在首个响应之前判断。

列表点开后自动标记已读使用本次真实快照，仍核对当前选择及列表的更新时间；主动通过菜单标记和旧标记核对仍走原有验证。草稿保存、会话激活、会话权限和写前核验的顺序不变。

## 记录归属

[最新消息首屏](../bug-fix/2026-11-20-chat-opens-at-latest.md)保留滚动定位和历史分页展示，本篇补齐首屏数据何时读取。[有界聊天更新](../bug-fix/2026-11-06-bounded-chat-updates.md)继续持有网络分页与订阅，[原生业务接入](../architecture/2026-11-10-native-web-parity.md)继续持有身份和写入边界。[模型目录预取](../architecture/2026-11-15-web-client-ui.md)、[聊天附件缓存](../bug-fix/2026-11-20-chat-image-cache-and-preview.md)和[会话菜单延迟](../bug-fix/2026-11-20-chat-menu-latency.md)分别持有模型、图片和菜单，无重复或可归档记录。云聊天恢复提案仍独立处理认证和连接恢复，不被本篇取代。

## Alternatives considered

- 只缓存已经打开过的会话，可省掉猜错时的流量，但首次点开仍需等待一次完整网关往返。对列表中的第一条增加一次有限预读。
- 预读所有可见行能扩大命中率，但网关仍需要为每条读取会话和元数据，多项读取会与正在打开的会话竞争带宽；在没有命中率和网关负载数据前只预读一条。
- 持久化最近页能覆盖 App 冷启动，但会新增聊天正文落盘、删除和账号失效规则；当前仅使用同连接的短时内存，不改数据库格式。

## Testing

`test/session_prefetch_test.dart` 用可控快照阻塞夹具验证：列表显示后、点击前发出预读；预读完成且实时响应未到时可见预览但没有会话操作；在途命中仅一次请求且已读不重复取快照；失败时回退；不同账号、重连和内存清除不接纳旧缓存。`test/chat_preview_cache_test.dart` 验证行数、正文预算、附件剥离、过期和淘汰。

## Consequences

预读命中后，用户不必等点击后的完整往返才能看到内容；完全无数据的会话仍需实时读取。预读完成后再打开仍会同步，预读过但最终没有打开的会话会产生额外读取。可控延迟夹具证明了等待边界，未测线上真机点击到首帧的延迟和预读命中率。
