# Agent Note: 向上翻阅时加载更早的消息

Status: implemented

## Problem

阅读到当前历史页边缘时必须再点一次「更早的消息」，向上翻阅会被按钮打断。用户希望沿聊天时间线继续翻阅即可加载上一页。首屏仍须优先显示最近消息，不能因历史分页等待或跳回旧位置。

## Decision

移除「更早的消息」入口。在当前聊天的主滚动区向历史方向滚动、距离旧页边缘不超过 96 个逻辑像素时，使用已有游标请求一页。首屏布局、程序定位、向新消息方向滚动及嵌套的横向内容不触发请求。短列表允许用户继续向历史边缘拉动；请求期间只在旧页边缘显示带辅助功能标签的加载指示。同一次连续滚动最多开始一次请求，在途请求也不重复；失败后可通过下一次向历史边缘滚动重试。

追加的旧消息放在[最新消息首屏](../bug-fix/2026-11-20-chat-opens-at-latest.md)的历史侧，不重设视口位置。分页仅在前台认证会话有有效游标时运行。页边界、账号或历史代次改变时丢弃迟到结果；只有在旧页边界不变时，运行中的正常消息追加与分页并行。网关返回历史重置、代次不符或不前进的游标时停止使用该分页链。只读预览不持有游标，也不能触发分页。

## 记录归属

[最新消息首屏](../bug-fix/2026-11-20-chat-opens-at-latest.md)的显式按钮触发规则由本篇取代，首屏布局、工作台保留位置以及两侧列表的定位规则不变。[有界聊天更新](../bug-fix/2026-11-06-bounded-chat-updates.md)持有网关分页和实时读取的协议，[会话列表预读](2026-11-20-chat-list-prefetch.md)持有最近一页的数据准备。未发现需要归档或废弃的相关记录。

## Alternatives considered

- 仅在旧页按钮进入可见区域时触发，几乎不需要判断滚动方向；短会话、字号变化或布局重算时也可能立即连续读取多页。改用朝历史边缘的用户滚动触发。
- 保留按钮能够让流量完全显式、失败后可直接点重试；但常规翻阅多一个动作，且不满足用户移除按钮的要求。通过每次滚动和每个游标的约束控制读取量。

## Testing

`test/ui_surface_layout_test.dart` 从长短会话发起真实拖动，验证手机和宽屏打开时无隐式历史请求、没有按钮，长会话并发拖动只请求一次，新页追加后已有行坐标不变，读完后停止。短会话分别覆盖 iOS 回弹和 Android 夹紧行为。`test/view_model_test.dart` 验证同边界的实时追加保留在途页，边界变化时忽略迟到页，重复游标停止分页。

Flutter 全量 580 项通过、5 项按条件跳过，静态分析无问题。核对浅深色差异后更新 8 张会话截图，变化仅为按钮消失。iPhone 18 Pro 模拟器覆盖安装后启动成功，构建二进制与安装版本一致，应用首次启动前的数据库和云配置哈希保持一致。

## Consequences

向上翻阅不再中断于按钮。每次继续翻阅最多产生一次按需旧页请求；网关延迟仍会在旧页边缘表现为加载时间。首次进入只等待最新页，程序化跳转也不会预取旧页。真实云链路耗时不由合成回归推断。
