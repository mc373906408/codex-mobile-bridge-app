# Agent Note: 选定电脑后扫码，只替换该连接

Status: implemented

## Problem

登录后自动生成待授权关系，重登或整机重新登记后出现多条同名手机。用户不能轻易找到正确授权，单台电脑的密钥故障也迫使其他电脑重新批准。

## Decision

登录只显示同账号电脑。点未配对电脑才申请一条绑定；已验证电脑直接重连。手机使用现有扫码控件，核对绑定 ID 和完整 Noise 指纹后提交桌面随机挑战。桌面明确批准后，仍以新绑定加密证明核验权限，再进入聊天列表。粘贴同一二维码载荷复用同一校验，非备用授权协议。

「重新配对」请求只带当前电脑的旧绑定 ID，不轮换安装身份或移除其他电脑。服务端在新授权获准时撤销选定旧绑定。旧草稿、待核对写入及账号数据保持原作用域；不根据名字迁移。已过期或撤销的旧 ID 不可恢复权限。

云服务中心的「本机配对 ID」按当前账号的电脑显示已核验安全码末 8 位，与桌面设备名后的短码同源。不同电脑的绑定可能显示不同短码。离线电脑已有的有效安全码仍可查看。没有可核验安全码时不构造替代值。

## 记录归属

[设备身份恢复](../bug-fix/2026-11-19-cloud-device-identity-recovery.md)的整机重新登记由本篇替代；仍沿用安全存储优先和原密钥不覆盖的规则。[配对响应错误](../bug-fix/2026-11-19-cloud-pairing-response.md)继续持有失败阶段诊断，[连接与重连](../bug-fix/2026-11-05-connecting-conversation-list.md)继续持有原身份重连行为。旧聊天恢复提案独立，无重复或需归档记录。

## Alternatives considered

- 整机重新登记能绕开丢失的单条预览密钥，但牵连每台电脑并产生新身份，因此只在坏绑定处发起更换。
- 恢复旧设备的安全码能免去确认，但缺失原密钥时无法可靠恢复。保留一次扫码与桌面明确批准。

## Testing

Rust 用合成目录与绑定验证只读发现、精确目标写入、二维码指纹与绑定拒绝；Flutter 回归覆盖损坏配对、不可授权的待确认状态及扫码后自动连接。未使用真实云账号或实体手机验收。

2026-11-20 本轮构建的 Flutter 静态检查、65 项界面测试、7 项 Rust 配对用例、11 项真实 FFI 用例和桌面 HTTP 契约均通过。iOS 27.2 模拟器覆盖安装成功，启动前 SQLite 摘要一致，安装后的程序和 Flutter 内核与构建一致。iOS 自签 IPA 与 Android arm64 测试 APK 已校验。设备枚举仅发现 iOS 模拟器，真机安装及扫码尚未验收。

同日的配对 ID 更新使用上一版已验证的 iOS 源码构建。19 项云页面和聊天菜单界面测试以及静态检查通过。离线电脑的已有短码与桌面的取值一致，未配对电脑不生成短码。iPhone 模拟器覆盖安装并启动，启动前数据库摘要一致，安装后的程序及 Flutter 内核与构建一致。自签 IPA 已校验，实体 iPhone 缺少可用的签名身份，尚未安装。

## Consequences

一次错误只影响一台电脑，用户无需抄写指纹或轮换其他连接。新配对使用三端匹配版本。已有已批准绑定以及恢复密钥的路径仍可使用。
