# 应用内 P2P

云设备仍使用原账号、桌面批准和设备密钥。两端及服务器支持 `easytier-v1` 时先接通云中继，再后台尝试 P2P；成功后新请求走直连。界面显示实际连接方式，原生状态接口提供两条路径的收发字节数。

服务端控制链路发送授权变化信令；客户端取得与当前身份匹配的明确失效结果后关闭连接。服务器不可达、超时及临时错误不关闭已有 P2P。新会话必须在线验证，已发送且结果未知的写入不会因重连重发。用户在桌面关闭连接、退出账号和更换账号立即终止相应访问。

## iPhone 验收

使用 macOS CI 的 `ios-p2p-for-user-signing-*` 产物，按现有签名流程签名安装；未签名 IPA 不能直接安装。保留原 Bundle ID、Keychain/App Group 和有效配置文件，不卸载清库。

1. 同账号打开已经批准的桌面，先确认云中继可用，再看到 P2P 直连。
2. 聊天读取、事件更新、图片上传/下载并发进行，查看直连字节增长。
3. 切换 Wi-Fi/蜂窝、后台再前台，确认自动恢复且没有重复发送消息。
4. 仅阻断云服务器时，存活的直连仍可读取；恢复云通信后明确到期/撤销必须关闭访问。
5. 桌面本地禁止该手机立即关闭访问；退出或新建连接在云不可达时不能通过。
6. 禁用 UDP/打洞后仍能使用云中继；设备上已有 VPN 不应被替换。

CI 编译、协议夹具不代表 iPhone 真机网络、后台存活、电量或签名验收通过。

## 对应源码

EasyTier 是 LGPL-3.0 组件，固定上游提交见 `third_party/bridge-p2p/source.json`。
构建产物附带 `bridge-p2p-corresponding-source.tar.gz`，含完整 EasyTier、应用源码、
锁文件、平台构建适配和构建脚本。替换库后按 `scripts/build_android.py` 或
`scripts/build_ios.py` 重新链接；移动端安装需使用自己的签名。第三方源码的许可
保持独立，应用与封装自有代码保持 MIT。
